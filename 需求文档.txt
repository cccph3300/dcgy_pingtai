入账订单管理系统开发任务

请根据以下完整需求，开发一个我个人使用的「入账 / 点单 / 订单 / 库存 / 提现记录」Web App。

这是一个部署在我自己的服务器上、主要通过手机浏览器使用的个人业务系统。

技术栈必须使用：

- 前端：Vue 3
- 构建工具：Vite
- UI：移动端优先，可以使用 Element Plus，但移动端界面必须自己适配，不能直接照搬 PC 页面
- 后端：Python FastAPI
- 数据库：MySQL
- ORM：SQLAlchemy 2.x
- 数据校验：Pydantic
- API：RESTful API
- 前后端分离
- 数据全部保存到服务器 MySQL
- 前端不能把核心业务数据只保存在 localStorage
- 可以使用 localStorage 保存登录状态、UI 状态等非核心数据
- 后端必须提供完整 API
- 项目最终可以部署到 Linux 服务器
- 推荐 Docker Compose 部署
- Web Server 使用 Nginx
- 前端构建后由 Nginx 提供静态文件
- "/api" 请求反向代理到 FastAPI
- MySQL 使用 Docker 或服务器 MySQL 均可

三、非常重要：车号右边的「＋」到底是什么意思

这是本项目最重要的交互规则。

表格右边每一行都有一个「＋」。

例如现在：

车号：

粤A12345

货物：

苹果

件数：

20

金额：

1000

利润：

100

右边有：

「＋」

点击这个＋，不是新增一个新的车号。

而是：

在「粤A12345」这个车号下面新增一条货物记录。

例如原来：

粤A12345    苹果    20    1000    100    ＋

点击＋之后变成：

粤A12345    苹果    20    1000    100    ＋
            葡萄    30    3000    300    ＋

再点击葡萄这一行的＋：

粤A12345    苹果    20    1000    100    ＋
            葡萄    30    3000    300    ＋
            香蕉    10     500     50     ＋

也就是说：

一个车号可以拥有多个货物。

数据库设计必须支持：

一个订单
    ↓
一个车号
    ↓
多个货物明细

而不是：

一个车号只能对应一个货物

六、金额和利润自动计算

例如库存中的苹果：

超市一：

售卖价：5.50元

抽佣价：0.50元

如果：

件数 = 20

那么：

销售金额 = 20 × 5.50

抽佣金额 = 20 × 0.50

利润按照系统配置的利润规则计算。

这里不要把计算逻辑写死在前端。

利润计算必须以后端为最终结果。

前端可以实时预览，但是提交订单时必须由 FastAPI 后端重新计算，防止用户篡改金额。

十七、金额调整规则

这个规则非常重要。

如果：

商品总金额 = 4500

然后：

运费 -100

补贴 +200

那么：

最终超市金额：

4500 - 100 + 200

= 4600

也就是说：

备注 / 费用调整只影响该超市的最终总金额。

默认：

不影响商品利润。

除非以后增加特殊的费用类型，否则不要自动改变利润。

二十八、后端安全要求

虽然这是个人使用，但是后端仍然必须做好基础安全。

至少：

- 密码不能明文保存
- 使用 bcrypt / passlib 或同等方案
- API 需要登录认证
- JWT 或安全 Session 均可
- 所有业务数据必须根据当前用户过滤
- 防止 SQL 注入
- Pydantic 校验请求参数
- 金额必须使用 Decimal / MySQL DECIMAL
- 不允许使用 float 存储金额
- 数量根据业务需要使用 Decimal
- 数据库操作使用事务
- 保存订单失败时必须回滚
- 删除商品时不能影响历史订单

---

所有金额：

- 成本

- 利润
- 提现金额
